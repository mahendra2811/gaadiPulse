# Localization implementation handoff — 2026-11-28

## Implemented

- `src/lib/i18n/locales/en.json` remains the sole English source catalog with 1,229 strings across 16 domain groups.
- Added `src/lib/i18n/locales/registry.json` as the single registry for app-enabled locales, catalog paths, display-name keys, native names, direction, and translation status.
- Runtime lookup still falls back to English for unknown locale codes and missing or blank translation values. Profile validation, Settings choices, and Expo native localization language codes now derive from the registry.
- Kept Hindi selectable as `partial`; its Settings hint identifies the English fallback. The 43 other locale JSON files stay unregistered drafts.
- Added active-locale date, number, and money formatters. Stored ISO timestamps and integer minor-unit amounts are unchanged.
- Added `scripts/check-locales.mjs`, `npm run i18n:check`, strict `npm run i18n:check:complete`, and focused fallback, registry, formatting, and direction tests.
- Expanded the locale README with key/section/locale workflows, incomplete-catalog rules, validation commands, and RTL release requirements. Recorded the registry decision in `docs/DECISIONS.md`.

## Translation coverage and remaining work

`npm run i18n:check` reports 1,229 English keys. Hindi has 137 populated strings and 1,092 blank values; each of the other 43 non-English catalogs has 0 populated strings. They are not complete translations, and linguistic review has not occurred. This implementation does not satisfy the requested full translation of all locales. Do not mark Hindi or any draft locale complete until translated and reviewed. The strict completion command intentionally fails because Hindi is partial.

RTL direction is represented in registry metadata and exposed by `getLocaleDirection()`. No RTL language is enabled, and native/web RTL layout is not implemented or device-verified. Complete that wiring and device QA before adding an RTL locale to the registry.
