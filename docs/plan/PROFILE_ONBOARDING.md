# Profile onboarding implementation plan

1. Route authenticated accounts without a saved display name to `/onboarding`; keep established profiles and recovery/legal routes working, and preserve old `/settings/profile` deep links by redirecting incomplete profiles. Keep profile-load failures recoverable.
2. Use a single short, scrollable, accessible form with a low-height full-width banner using the supplied local GaadiPulse artwork and existing logo. Collect a name, optional country and editable IANA time zone. Completing profile setup must not require adding a vehicle; vehicle creation remains available afterwards.
3. Treat device language/region and time zone only as editable suggestions, not as evidence of residence or current location. Suggest a time zone on a country change only where the bundled data has an unambiguous supported zone, and never replace an explicitly selected time zone. Multiple-zone or unknown countries require a user choice; never infer GPS.
4. Be explicit that the existing ledger records INR paise. Do not present a selectable non-INR currency as working: safe multicurrency needs per-record currency, server enforcement, legacy-client compatibility and separate reporting as described in `INTERNATIONAL_COUNTRY_CURRENCY_ONBOARDING.md`. The onboarding screen should disclose the present INR limitation.
5. Reuse the existing authenticated profile write, preserve the current name from signup when available, keep existing country/icon/time-zone fields intact, validate form values and surface recoverable failures. Save the basic profile before navigating Home; allow sign-out and leave optional fields unset rather than invent data.
6. Validate first login and restored sessions, route gates and legacy links, device-region and timezone suggestions, multi-zone countries, manual overrides, errors, and existing accounts. Run relevant type, lint, unit and Expo checks and record device/backend limitations in the handoff.
